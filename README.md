# InvoiceGeneratorNow - Public Launch Build

A self-contained PHP + SQLite SaaS for small service businesses, configured for InvoiceGeneratorNow.com.

## Core workflow
Customer → Quote → Follow-up → Won/Job → Invoice → Due/Overdue → Paid.

## Included
- Account registration/login with password hashing and CSRF protection
- Enquiry/lead capture with one-click conversion to customer
- Customer database
- Editable customer profiles with quote and invoice history
- Itemised quotes with tax, expiry, follow-up date and printable PDF workflow
- Public quote accept/decline link
- Convert quote to job
- Convert quote to invoice
- Jobs list
- Itemised invoices with due/overdue/paid tracking
- Aged-debt report with not-due, 1–30, 31–60, 61–90 and 90+ day buckets
- Password-reset flow and login rate limiting
- Trial expiry and paused-account access controls
- Email verification, registration/contact throttling and expiring password-reset links
- Recurring jobs generated by the daily cron
- Full-account JSON download and permanent account deletion
- Daily SQLite backup script with 30-day on-host retention
- Static bank-transfer details (display only; no payment processing)
- Country-first global setup covering 250 countries and territories and 153 currencies: choosing a country selects its usual currency automatically, with manual override and fully custom code, name, symbol, placement, separators and 0–4 decimal places
- Quote and invoice follow-up dashboard
- Expense records
- CSV exports
- Daily reminder and recurring-job cron
- Contact form that stores messages without exposing a contact email
- Manual plan/status admin screen
- Landing, features, pricing, privacy, terms, robots.txt, sitemap and SEO landing pages

## No paid APIs
The core app uses PHP + SQLite only. No OpenAI, Stripe, Twilio, Xero, QuickBooks or other paid API is required.

## Payment boundary
This app intentionally has no payment link, checkout, card collection, wallet or payment verification. A business may display its own static bank-transfer details on an invoice, but the app does not initiate, receive, hold, route, process or verify money.

## Local test
From the project root:

```bash
php tests/smoke.php
php -S 127.0.0.1:8080 -t public_html
```

Then visit `http://127.0.0.1:8080`.

## Hostinger/Fasthosts-style deployment
1. Put the contents of `public_html/` into the site's public web directory.
2. Put `app_private/` and `storage/` one directory above `public_html` so they cannot be downloaded from the web.
3. Ensure PHP has PDO SQLite enabled and the `storage/` directory is writable by PHP.
4. Keep the supplied application URL, contact email and administrator email, or override them in a private `secrets.php`.
5. Follow `EMAIL-SETUP.md` to configure authenticated SMTP, SPF, DKIM and DMARC.
6. Run `cron/daily.php` and `cron/backup.php` daily.
7. Force HTTPS in your hosting panel before launch.

## Public launch

Follow `LAUNCH-CHECKLIST.md`. The code is packaged for launch, but the owner must supply accurate legal/business details, live-domain email configuration and hosting credentials. Subscriptions must be collected separately because this application intentionally contains no payment processing.

## V18 update — flattened to the repository root (Hostinger 403 fix, matches the network)
- **Restructured so all web files live at the repository root** (index.php, assets/, robots.txt, sitemap.xml, favicons, the IndexNow key, .htaccess), the same layout as the rest of the network (e.g. TapPill). The previous `public_html/` nesting was the cause of Hostinger's 403, because Hostinger publishes the repo root as the document root.
